BACKEND PROJECT LEARNING GUIDE
=============================

This file explains the backend of this project in a beginner-friendly way.
It covers all important code files in the backend, without skipping any code files.
Images and non-code files were intentionally ignored.

PROJECT TYPE
------------
This backend is a Django REST API project for an e-commerce website.
Main technologies:
- Python
- Django
- Django REST Framework (DRF)
- SQLite database
- JWT token authentication
- CORS for frontend communication

The backend manages:
- user registration and login
- store categories and products
- shopping cart items
- orders and payments
- AI chat support
- notifications and settings
- profile data

THINK OF THE BACKEND LIKE THIS
-----------------------------
A backend works like this:
1. The frontend sends an HTTP request.
2. Django receives the request.
3. URL pattern decides which app handles it.
4. View function or ViewSet reads or updates database data.
5. Serializer converts Python objects to JSON and vice versa.
6. The frontend receives JSON data.

In this project, the frontend sends requests like:
- /api/store/products/
- /api/cart/cart-items/
- /api/orders/orders/
- /api/accounts/register/

IMPORTANT BEGINNER CONCEPTS USED IN THIS PROJECT
--------------------------------------------------
1. Model = database table definition
   Example: Product, Order, Cart, User

2. Serializer = JSON translator
   It converts database objects into JSON to send to frontend.

3. View / ViewSet = business logic
   It receives requests, checks permission, queries database, returns response.

4. URL routes = path mapping
   It tells Django: 'If user calls this URL, use this view'.

5. Permissions = access control
   Example: only logged-in user can view own cart

6. JWT = token-based auth
   Frontend stores accessToken and refreshToken in localStorage.

FILE: Back/manage.py
Purpose:
This is the main entry point for the Django project.
It starts the server and runs commands such as:
- python manage.py runserver
- python manage.py migrate
- python manage.py createsuperuser

Code meaning:
- os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'backend.settings')
  This tells Django which settings file to use.
- execute_from_command_line(sys.argv)
  Runs Django CLI command from terminal.

Why it matters:
Without this file, Django has no app start command.

FILE: Back/requirements.txt
Purpose:
Lists all Python dependencies required by the project.

Important packages:
- Django==4.2.30 -> web framework
- djangorestframework -> API library
- django-cors-headers -> allows browser requests from frontend
- djangorestframework_simplejwt -> JWT auth
- Pillow -> image handling

This project uses SQLite, so no database server installation is required.

FILE: Back/backend/settings.py
Purpose:
This is the heart of the Django project configuration.
It controls:
- installed apps
- database config
- auth model
- middleware
- CORS
- JWT config
- media/static paths

Important sections:

1. BASE_DIR and SECRET_KEY
- BASE_DIR tells Django where project root is.
- SECRET_KEY is used for security and sessions.
- DEBUG = True means development mode.

2. ALLOWED_HOSTS
- Lists allowed network hosts.
- Includes localhost and 0.0.0.0.

3. INSTALLED_APPS
- django.contrib.admin -> admin site
- django.contrib.auth -> authentication system
- django.contrib.contenttypes -> content-type support
- django.contrib.sessions -> session support
- django.contrib.messages -> flash messages
- django.contrib.staticfiles -> static files support
- rest_framework -> DRF
- corsheaders -> CORS support
- accounts, cart, chat, core, orders, store -> project apps

4. AUTH_USER_MODEL = 'accounts.User'
- This tells Django to use the custom User model from accounts app instead of the default one.

5. MIDDLEWARE
- CORS middleware is placed at top so frontend requests are accepted.
- SecurityMiddleware protects base requests.
- SessionMiddleware enables session tracking.
- CommonMiddleware handles standard request handling.
- CsrfViewMiddleware protects CSRF attacks.
- AuthenticationMiddleware attaches user object to requests.

6. DATABASES
- Uses SQLite database at Back/db.sqlite3.
- SQLite is simple and great for local development.

7. REST_FRAMEWORK config
- DEFAULT_AUTHENTICATION_CLASSES includes JWTAuthentication.
- This means API endpoints require token auth unless permission says otherwise.

8. SIMPLE_JWT config
- ACCESS_TOKEN_LIFETIME = 60 minutes
- REFRESH_TOKEN_LIFETIME = 7 days
- ROTATE_REFRESH_TOKENS = True
- AUTH_HEADER_TYPES = ('Bearer',)
- This matches frontend pattern: Authorization: Bearer <token>

9. CORS_ALLOWED_ORIGINS
- Frontend URLs allowed to connect:
  - http://localhost:3000
  - http://localhost:5173
  - http://127.0.0.1:5173
- This allows Vite/React frontend to talk to Django backend.

10. MEDIA and STATIC settings
- MEDIA_URL = '/media/'
- MEDIA_ROOT = .../media
- STATIC_ROOT = .../staticfiles
- This allows product/category images and other uploaded files to be served.

FILE: Back/backend/permissions.py
Purpose:
Custom permission classes.
These decide who may access which endpoint.

1. IsCustomerUser
- Only allows authenticated users with is_customer = True.
- Useful if some endpoints require only customers.

2. IsSupportAgentUser
- Allows authenticated support agents or staff users.
- This is used for chat and inventory support.

3. IsOwnerOrStaff
- Object-level permission.
- Allows the user to act on their own profile/cart/order only.
- Staff can also access everything.

How it works:
- If object has .user, compare obj.user == request.user
- If object has .user_id, compare with user.id
- Works for nested relationships such as cart -> user or session -> user

This is important because it prevents one user from viewing another user’s data.

FILE: Back/cart/serializers.py
Purpose:
Handles conversion of cart and cart-item objects to JSON.

CartItemSerializer

create() method
- Gets current request user.
- Gets or creates cart for that user.
- If same product already exists, quantity increases.
- Saves price_at_add snapshot.

update() method
- If quantity <=0, delete item.
- Otherwise update quantity.

Why this is important:
Cart logic is not in frontend only; backend ensures consistent cart data and price snapshots.

HOW THE BACKEND WORKS AS A WHOLE
--------------------------------
The backend flow is:
1. Browser asks frontend to log in.
2. Frontend POSTs to /api/token/.
3. Backend validates username/password and returns JWT tokens.
4. Frontend stores access token in localStorage.
5. Frontend makes authenticated requests with Authorization: Bearer <token>.
6. Django REST Framework checks the token.
7. ViewSet checks permission rules.
8. Database query returns data.
9. Serializer turns data into JSON.
10. Frontend renders the result.

EXAMPLE: LOGIN FLOW
-------------------
- frontend sends username/password to /api/token/
- Django SimpleJWT creates access + refresh tokens
- frontend stores them in browser localStorage
- later requests include Authorization header

EXAMPLE: ORDER FLOW
-------------------
1. Frontend fetches cart items.
2. User enters shipping/billing/payment info.
3. Frontend posts to /api/orders/orders/
4. Backend creates order
5. Backend copies cart items into order items
6. Backend deletes cart items
7. Frontend navigates to order history page

EXAMPLE: PRODUCT FLOW
---------------------
1. Frontend fetches /api/store/products/
2. ProductViewSet filters active products.
3. Serializer includes product image and inventory data.
4. Frontend displays cards and detail pages.

WHY THIS BACKEND IS GOOD FOR A BEGINNER
---------------------------------------
This backend teaches important real-world patterns:
- models define tables
- serializers structure JSON responses
- viewsets handle HTTP logic
- permissions protect user data
- routers simplify URL creation
- JWT handles auth without storing sessions in server memory

If you want to become a Django developer, learn these ideas first:
- model relationships
- queryset filtering
- JSON/API design
- request/response cycle
- authentication and authorization

COMMON LEARNING QUESTIONS EXPLAINED
-----------------------------------
Q: Why use serializers instead of raw SQL?
A: Because Django ORM manages database access cleanly and serializers make JSON output easy.

Q: Why use a custom User model?
A: To add fields like email, phone, and customer flags.

Q: Why use DecimalField for money?
A: To avoid errors in currency calculations.

Q: Why are permissions important?
A: So users cannot access each other's data.

Q: Why are URLs under /api/...?
A: To separate API routes from frontend routes and keep API logical.
