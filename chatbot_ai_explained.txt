BEGINNER-FRIENDLY EXPLANATION OF THE CHATBOT AI SYSTEM
=====================================================

This file explains the chatbot AI part of the project in a simple way so a beginner can learn how it works by reading the code. I focused on the actual code files used for the AI chatbot and the frontend/backend connection. I skipped images and non-code assets.

IMPORTANT BIG PICTURE
---------------------
The project has three layers:
1. Frontend (React app in my-app)
2. Backend API (Django REST Framework)
3. AI engine (Ollama + chatbot logic)

The flow is:
- User types a message in the browser.
- React frontend sends a POST request to the backend.
- Django receives the request.
- Input is cleaned and checked by the AI firewall.
- The backend builds product or business data snapshot from the database.
- The model receives that snapshot and the user question.
- The AI generates a reply.
- Output is checked again.
- The backend returns the reply to the frontend.
- Frontend shows the message in the chat UI.

This project has two chatbot modes:
- Customer chatbot: public help for shopping questions
- Admin chatbot: private business assistant for staff/admin checks

NEXT: TEXT NORMALIZATION
------------------------
These regex patterns clean the input so harmless hidden characters or whitespace do not bypass checks.

_ZERO_WIDTH_RE = re.compile(r"[\u200B-\u200D\u2060\uFEFF]")
_CONTROL_RE = re.compile(r"[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]")
_WHITESPACE_RE = re.compile(r"\s+")

What they do:
- Zero-width characters are invisible text tricks used in prompt injection.
- Control characters are hidden special characters.
- Whitespace regex collapses repeated spaces into a single space.

The function normalize_input(text):

def normalize_input(text):
    """Normalize user text before security checks and before sending to Ollama."""
    if not isinstance(text, str):
        return ""

    normalized = unicodedata.normalize("NFKC", text)
    normalized = _ZERO_WIDTH_RE.sub("", normalized)
    normalized = _CONTROL_RE.sub("", normalized)
    normalized = _WHITESPACE_RE.sub(" ", normalized)
    return normalized.strip()

This is extremely important.
- It converts weird unicode to a clean normal form.
- It removes hidden attack characters.
- It normalizes spaces.
- It gets the text ready for checking by AI security rules.

This function is called before sending any user message to the AI.

NEXT: GENERAL BLOCKED ATTACK PATTERNS
------------------------------------
The code defines protected attack patterns.

_GENERAL_INPUT_PATTERNS = (
    re.compile(r"\bignore\b.{0,50}\b(previous|prior|all|system|developer)\b"
               r".{0,50}\b(instruction|instructions|rules|prompt|message)\b", re.IGNORECASE),
    re.compile(r"\b(reveal|show|print|repeat|dump|expose)\b.{0,50}"
               r"\b(system prompt|hidden prompt|developer message|hidden instructions)\b", re.IGNORECASE),
    re.compile(r"\b(jailbreak|prompt injection|bypass safety|bypass security)\b", re.IGNORECASE),
    re.compile(r"\b(reveal|show|print|give|dump|expose)\b.{0,50}"
               r"\b(password|secret key|api key|access token|refresh token|jwt|credential|credentials)\b",
               re.IGNORECASE),
)

These patterns detect things like:
- ignore previous instructions
- reveal system prompt
- jailbreak or bypass safety
- ask for passwords or tokens

This is a common security check used in AI applications.

NEXT: CUSTOMER-SPECIFIC SECURITY RULES
-------------------------------------
Public customers should not be able to access admin or private business data.

_CUSTOMER_SENSITIVE_PATTERNS = (
    re.compile(r"\b(act|pretend|switch|enter)\b.{0,30}\badmin\b", re.IGNORECASE),
    re.compile(r"\b(admin mode|database dump|dump the database|database snapshot)\b", re.IGNORECASE),
    re.compile(r"\b(show|list|reveal|give)\b.{0,30}\ball users\b", re.IGNORECASE),
    re.compile(r"\bcustomer emails?\b", re.IGNORECASE),
    re.compile(r"\b(total users|total orders|latest orders|order details)\b", re.IGNORECASE),
    re.compile(r"\b(sales revenue|total revenue|sales value)\b", re.IGNORECASE),
    re.compile(r"\b(exact stock|stock count|inventory count|how many units)\b", re.IGNORECASE),
)

What these rules block:
- pretending to be an admin
- database dump requests
- asking for all users or emails
- asking for finances and exact stock counts

This ensures the customer chatbot is limited to public catalog questions only.

NEXT: JWT AND SECRET DETECTION
------------------------------
These regexes look for sensitive information in AI output before it reaches the browser.

_JWT_RE = re.compile(r"\beyJ[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{5,}\b")

This catches JWT values, which often look like:
eyJsomething.abc.xyz

_SECRET_ASSIGNMENT_RE = re.compile(
    r"(?i)\b(secret[_ -]?key|api[_ -]?key|password|database[_ -]?password|"
    r"access[_ -]?token|refresh[_ -]?token|auth[_ -]?token)\b\s*[:=]\s*"
    r"[\"']?[^\s\"']{4,}"
)

This catches patterns like:
password = abcdef
api_key: "xyz"

_BEARER_RE = re.compile(r"(?i)\bauthorization\s*:\s*bearer\s+[^\s]+")
This catches Authorization: Bearer ... headers.

_DB_URL_RE = re.compile(
    r"(?i)\b(?:postgres(?:ql)?|mysql|mongodb(?:\+srv)?)://[^\s:@/]+:[^\s@/]+@"
)
This detects database connection strings such as postgres://user:pass@host/db.

_DJANGO_SECRET_RE = re.compile(r"(?i)django-insecure-[^\s\"']+")
This catches Django secret keys that should stay hidden.

_PROTECTED_PROMPT_MARKERS = (
    "you are the public customer shopping assistant for bestcommerce",
    "you are the private admin assistant for bestcommerce",
)

This checks if the AI accidentally leaked its hidden system prompt text.

NEXT: CHECK FUNCTIONS
---------------------
The function check_input(message, customer_mode=False):

def check_input(message, customer_mode=False):
    """Return (allowed, reason) for normalized user input."""
    if not isinstance(message, str) or not message.strip():
        return False, "invalid_or_empty_input"

    for pattern in _GENERAL_INPUT_PATTERNS:
        if pattern.search(message):
            return False, "prompt_injection_or_security_request"

    if customer_mode:
        for pattern in _CUSTOMER_SENSITIVE_PATTERNS:
            if pattern.search(message):
                return False, "protected_business_data_request"

    return True, None

What it does:
- Rejects empty message
- Rejects general malicious requests
- If it is a customer chatbot request, it also blocks secret business questions
- Returns True or False with a reason

The function check_output(reply):

def check_output(reply):
    """Return (allowed, reason) before an Ollama response reaches the frontend."""
    if not isinstance(reply, str):
        return False, "invalid_ai_output"

    if _JWT_RE.search(reply):
        return False, "jwt_leak_detected"

    if _SECRET_ASSIGNMENT_RE.search(reply):
        return False, "sensitive_data_leak_detected"

    if _BEARER_RE.search(reply):
        return False, "bearer_token_leak_detected"

    if _DB_URL_RE.search(reply):
        return False, "database_credential_leak_detected"

    if _DJANGO_SECRET_RE.search(reply):
        return False, "secret_key_leak_detected"

    lowered = reply.lower()
    if any(marker in lowered for marker in _PROTECTED_PROMPT_MARKERS):
        return False, "system_prompt_leak_detected"

    return True, None

This is a final protection step before sending the AI message to the user.

        "blocked": False,

This sends the safe AI answer back as JSON to the client.

export function getImageUrl(image) {
  if (!image || typeof image !== "string") return "";

  if (image.startsWith("http://") || image.startsWith("https://") || image.startsWith("data:")) {
    return image;
  }

  const base = API_BASE ? API_BASE.replace(/\/$/, "") : "";

  if (image.startsWith("/media/")) {
    return base ? `${base}${image}` : image;
  }

  const normalizedPath = image.startsWith("/") ? image.slice(1) : image;
  const origin = typeof window !== "undefined" ? window.location.origin : "";

  if (normalizedPath.startsWith("media/")) {
    return base ? `${base}/${normalizedPath}` : `${origin}/${normalizedPath}`;
  }

  return base ? `${base}/media/${normalizedPath}` : `${origin}/media/${normalizedPath}`;
}

This is not directly part of the chatbot, but it helps with images in the app and is often used widely across the frontend.

Then the sendMessage function:

async function sendMessage(e) {
  e.preventDefault();
  if (!message.trim()) return;

  const userMessage = message;
  setMessages((prev) => [...prev, { sender: "You", text: userMessage }]);
  setMessage("");

  try {
    const response = await fetch(`${API_BASE}/api/ai/chat/`, {
      method: "POST",
      headers: getJsonHeaders(),
      body: JSON.stringify({ message: userMessage }),
    });

    const data = await response.json();

    if (!response.ok) {
      const errorText = data.detail || data.message || "Unable to send chat message.";
      setMessages((prev) => [...prev, { sender: "AI", text: errorText }]);
      return;
    }

    setMessages((prev) => [...prev, { sender: "AI", text: data.reply }]);
  } catch {
    setMessages((prev) => [...prev, { sender: "AI", text: "Unable to connect to the server." }]);
  }
}

What this does:
- Prevents sending empty message.
- Adds the user message to chat immediately.
- Sends a POST request to /api/ai/chat/.
- Sends JSON with the message field.
- Reads JSON response.
- If server response is not okay, shows error.
- Otherwise, displays AI reply.

SECTION 12: HOW THE ENTIRE AI SYSTEM WORKS STEP BY STEP
--------------------------------------------------------
Here is the full request life cycle.

1. User opens the front-end page.
   - The React page loads the chat UI.
   - It keeps an array of messages in state.

2. User types a question.
   - Example: "Which products are under 2000 taka?"
   - The message goes to the Chat component.

3. Front-end sends request.
   - The code calls fetch(`${API_BASE}/api/ai/chat/`)
   - JSON body: { "message": "..." }

4. Backend validates the request.
   - serializer ensures the message exists and is not empty.

5. Input firewall checks the message.
   - Since the user is a customer, it checks for privacy or prompt injection patterns.
   - If blocked, it returns a safe blocked_reply.

6. Product snapshot is built.
   - build_customer_product_snapshot() queries active products.
   - It creates plain-language product catalog information.

7. Model is called.
   - Ollama receives:
     a) system prompt (instructions)
     b) user question
     c) product snapshot
   - The AI answers using the allowed product information.

8. Output firewall checks the answer.
   - If the AI response contains secrets, leaked prompts, or dangerous data, it is blocked.

9. Response is sent back to frontend.
   - The React component adds the AI reply to the message list.

10. Admin route works similarly, but with stricter auth and a database snapshot.
